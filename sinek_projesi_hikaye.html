Genesis Fly — the story of the fly-brain calculator

A gated calculator built on a real Drosophila connectome.

What this is

A small arithmetic machine whose answers come from a simulated fly brain. The fly core does exactly one thing: a step from n to n±1 over a cell assembly that was calibrated from the FlyWire connectome. Everything else — counting, looping, the stop condition, the remainder — lives in an explicit controller. That division of labour is written into every answer the interface gives, so the reader always knows which part did the work.

Language rule of the project: results are reported as "in this data, with this model, on this grid". Nothing here is a claim about real flies.

Finding 1 — 16,000 two-digit trials, 99.84%

ProbeDesignResult
Two-digit / out-of-range inputs (exploratory) 20 seeds × 200 pairs × 4 operations = 16,000 trials 99.84% overall — add / subtract / multiply 100%, divide 99.35%

The pre-registration for this probe was committed before the measurement, and it is labelled exploratory: it does not change the pre-registered criteria of the main phase.

The losses are not in the fly core. They come from the controller: a quotient that reaches q ≥ 50 is rejected by the stop bound q < 50, so those trials are answered with an explicit error instead of a silently wrong number.

Finding 2 — the fake-fly collapse

To prove that the arithmetic really comes from the neural core, a fake core (a null model returning random output) was plugged in. Nothing else changed.

CoreMean agreement with the true resultNumber of core calls
Real calibrated core1.00005
Fake (null) core0.12355

The answers collapse while the call count stays identical (5 == 5): the controller is not secretly doing the maths, it only drives the core.

Finding 3 — the 36/81 division warning

Division has a trap that the first integrity run walked straight into. Of the 81 tested division pairs, 36 pairs never need the core at all (b ≥ a, so the answer is 0 or 1). A fake-fly test over those pairs therefore looks almost "fine" — a degenerate baseline of 0.4444 instead of the expected collapse.

That was a test-design error, not a result. It is now guarded explicitly: the integrity suite refuses to accept a fake-core run as proof when the operand set does not force the core to work. The honest number for the guarded run is the 0.1235 collapse above.

Honest limits (all of them)

  • Operands are 1..9 and results are 0..81 — the measured table of the shipped core (table accuracy 1.0000).
  • Negative results and results above 81 are rejected loudly, never clipped.
  • Division is integer quotient + remainder; there is no multi-digit arithmetic and the two-digit tens/units architecture was never implemented.
  • The state lives in the controller (counter, loop, stop condition, remainder); the fly only steps n→n±1.
  • This is a simulation of one connectome, not a live organism.
  • No connectome-specific task advantage was demonstrated in any phase.
